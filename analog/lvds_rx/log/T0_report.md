## How a testbench plugs in (T1-T4)
1. Create `sim/<tb>/<tb>.json` (+ deck) named exactly as in `spec/gates.yaml` (`spec:`); its `corners` must equal the gate's full-tier set,
   its `grid` must have exactly the listed parameters with the listed number of values, `mc.n` the listed full N (gates.py reports SCOPE otherwise).
2. The deck must write the metric names listed in the gate's `checks` (`.meas`/`meas`, or `echo RESULT name value`, or a post hook), SI units.
   Corner fields usable in `where:` filters: `process temp vdd corner res`; grid parameters too.
3. `python3 flow/run_all.py --tier smoke --only <GATE>` runs it at tt/worst5 (MC N=30) and evaluates it; `make smoke` runs all that exist.
4. The sizing script (T2) must write the header from `flow/common.py: sizes_header_lines()` at the top of `sizing/sizes.spice` and the netlist
   build must call `common.assert_fresh_sizes(path)`; it must also write `results/sizing.json` with `asserts_failed`, `nf_m_violations`, `tally_ok`
   (SIZE gate). The layout flow writes `results/layout.json` (LAYOUT gate keys in gates.yaml).
5. Circuit-specific mutants: `flow/mutants_<task>.py` with `from mutants import mutant` (see mutants.py docstring); `make mutants` loads them.

## Open / notes
- git does not work inside the container (worktree `.git` points at a host path); `flow/common.py` reads HEAD from files, the "dirty" flag is
  therefore `None` in manifests. Commits are made from the host.
- Plain PyYAML reads `3.25e9` (no sign) as a string; `common.load_yaml` has a patched loader. Use `common.load_yaml`, not `yaml.safe_load`, for spec files.
- `make smoke` is not green until the testbenches exist (16 gates NOT_RUN, TB11 NOT_APPLICABLE until ladder R6 rung 1). SIZE/LAYOUT/TBL are stubs by design.
- Expected counts per tier are in `python3 flow/run_all.py --tier full --dry-run` (TB3_off full = 15000, TB7_mc full = 1500 runs).
- `envcheck.py` snapshots and restores `layout/magic_flow/results/` because the toy regression rewrites those committed copies.
- Demo result files under `sim/harness_demo/results/` were regenerated by `run_demo.sh` (wnflag header); that is why they appear in the commit.
